# stead-urbit-release

Read AGENTS.md, the candidate task and operator approval boundary. Separate code publisher, organization operator, project authority and member identity. A publisher distributes executable code and belongs in the trust model; it does not receive company authority merely by naming a desk.

Assemble a self-contained desk from pinned dependencies, supported sys.kelvin, selected desk.bill agents and appropriate docket metadata. Publish stable developer marks separately from private state. Match frontend/glob digest to the source and desk release manifest. Do not refresh floating branches or rebuild mutable bundles during distribution.

Test clean install, supported predecessor migration, wrong Kelvin, old frontend/peer versions, unavailable publisher, corrupt artifact and interrupted job/update. Verify actual native update/pinning controls before advertising release channels. Reverting source is not automatically a saved-state downgrade.

Record source, artifact digests, toolchain/kernel/state/protocol versions, notices and operator instructions. Keep canary/stable promotion reviewed; test keys and synthetic data only unless explicitly authorized. A conventional offline bundle and export path must remain possible without a private service.

For recovery: use a consistent checkpoint, fence old authority, invalidate stale access, reconcile uncertain effects, and never run duplicate live ship identities. Stop, uninstall and data purge are distinct actions. Require independent evidence and human release/key/provisioning approval.
