# Support and compatibility

Current status: development experiment. No hosting SLA, production support promise, maintainer staffing or universal Urbit compatibility is implied.

Use an existing issue for implementation progress. For defects, provide source/runtime/kernel versions, supported installation profile, a minimal synthetic reproducer, expected/actual behavior and redacted logs. Do not attach a real pier or credentials. Before public beta, the release manifest and tested support matrix must state the exact supported host, runtime, Kelvin, frontend, protocol and state versions.

Contributor, app user, operator and integrator quickstarts have distinct responsibilities. Native desk installation distributes code, not company data. Optional Groundseg, managed hosting, Tlon, CDN or identity-provider profiles are supported only when specifically tested; no provider is mandatory by assumption.

Use SECURITY.md for sensitive reports. Broader stable support, deprecation and backup-maintainer procedures are URB-270/280 work, not completed by these starter documents.
