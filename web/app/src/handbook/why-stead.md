# Why Stead?

If someone asks “Why did we change this?”, I want to open one project and find the answer. In Stead, the task says what needed doing, the discussion explains the decision, and the page or Git commit shows what changed. That works for a visitor guide just as well as it does for a software release.

Every project starts with Work and Docs. Add Code when you need it. Your team runs its own Home and decides who can read and change the project. The writing is Markdown. The code is ordinary Git. You can take both with you.
