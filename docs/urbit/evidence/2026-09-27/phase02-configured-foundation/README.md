# Configured-team authority and read-model foundation

This increment contains pure native libraries and an unintegrated host ingress
fence. It does not close Phase 2, expose an HTTP/member endpoint, or establish a
browser/TLS journey. The live `stead-home` remains the legacy version-2 fixture
agent. No production identity, confidential dataset or public service was used.

## Behavior

The configured profile adds explicit current person bindings, immutable binding
ownership and revision high-water, a bounded project-creator list, general
projects, Work, private/shared document collections, selected-page publication,
tombstones, typed relations and current-authorized receipt recovery. Browser
attribution is created by the verified session context at acceptance. It is never
rewritten from fixture attribution. All configured commands use one final pure
authorization gate with role, scope, expiry, revision and epoch checks.

Publication writes only the selected page into the explicit shared destination,
using source and destination CAS. Its Git parent/tree come from the destination;
unselected private pages and private source commits remain unreachable there.
Search, relations, activity, inbox and pagination filter current authorization
before revealing fields or generations. Rebuild uses a separate bounded index,
rejects gaps/poison, and swaps after authoritative head/count verification.

Saved-state validation is consistency reconstruction, not independent proof of
historical identity approval. Internal journals retain nonsecret authentication
and grant-target snapshots. A private reconstruction reuses unchanged business
checks and compares the entire resulting state, including original Git objects,
receipts, grants and generations. Current binding removal, expiry or increased
revision does not reauthorize old history. Equal revisions must retain identical
identities. Jobs return no usable result until validation completes.

The host ingress primitive forwards opaque bytes only to a fixed fake ship's
secure port. It requires a correlated, one-use bootstrap acknowledgement for the
owned child lifetime, uses a pidfd, retires pending acknowledgements on disarm,
closes streams on child/guard failure, and refuses replacing a live child.
Its host tests use a dummy echo backend; supervisor port ownership and actual
native bootstrap/TLS are still integration obligations.
