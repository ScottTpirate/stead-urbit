# URB-170 optional editor tooling review — 2026-09-25

**Decision: do not adopt the reviewed Hoon language server for M0.** Keep it optional and unqualified. The exact upstream bridge source fails a host parser check on our pinned Node binary, before a ship connection is possible. This is a bounded compatibility rejection, not a claim that the pinned Hoon agent fails to compile. No package, editor extension, credential, ship agent, network exposure, or normal setup was changed.

Reviewer: `/root/editor_tool_review`, independent bounded review assigned by the integrator. Scope: the optional editor criterion in [URB-170 / issue #20](https://github.com/ScottTpirate/stead-urbit/issues/20), the [developer guide](../DEVELOPER_GUIDE.md), and the pinned fake-ship stack. The six-task skill evaluation and the rest of URB-170 are separate acceptance work.

## Credentials, storage and isolation

The [bridge source](https://github.com/urbit/hoon-language-server/blob/1024fbf219007e58605ae06c9314235abfdb42bd/src/server.ts#L184-L220) takes ship, URL, HTTP port and `+code` from CLI options and forwards the code to `urbit-airlock`'s `connect`. It provides no explicit secret-file, stdin, environment, or OS credential-store route. An editor configuration containing a real code would persist that secret; supplying it as an argument can expose it to process inspection or command history. No real code was obtained or used. The published example/default is for a fake ship and is not permission to use a live identity.

The bridge writes a fixed-name `hoon-language-server.log` in the OS temporary directory, and its source logs subscription update objects. The pinned [ship agent](https://github.com/urbit/urbit/blob/5a187fededc4582a34fcd6055c67bb63e0917b94/pkg/arvo/app/language-server.hoon) keeps editor buffers and build information in its versioned saved state; its save notification handler also requests a `%hood` desk commit. Treat submitted source, diagnostics, logs and fake-pier state as data copies. This review did not inspect `urbit-airlock`'s authentication/session internals and makes no claim about that dependency's cookie storage or redaction.

Our harness launches ships with loopback HTTP inside `bwrap --unshare-all`. A host editor's `localhost` is a different network namespace, so the upstream host-editor recipe cannot simply address these ships. Do not weaken that isolation, expose the authority host, or obtain live `+code` to make this optional tool work. A later adapter would need to keep the editor transport and public synthetic fixtures within an explicitly reviewed local boundary.

No native compatibility test is needed to support the present non-adoption decision: the retained bridge has an earlier, reproduced parser failure. If the bridge is repaired and reconsidered, the narrow first native probe for the integrator to queue through the existing guarded supervisor is `dojo('zod', '|start %language-server', timeout=180)` followed by `dojo('zod', '.^(? %gu /=language-server=/$)')`, requiring exactly `%.y` and retained source/Clay/guard bindings. These are **planned inputs**, not a new CLI command or an executed result. A compile/start pass alone would still leave actual HTTP authentication, LSP request/response, denied access, bounded logs, save behavior, and a pinned editor integration to test. Use only resettable fake state and synthetic source; normal development remains the documented compiler/test loop.

The optional-tool review can therefore be accepted as **evaluated and not adopted**, subject to integrator review. It does not certify editor functionality, close the remaining skill evaluation, or close all of URB-170.
